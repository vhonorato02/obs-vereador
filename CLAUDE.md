Plataforma pública do **Observatório Social do Brasil – Pindamonhangaba** para o cidadão acompanhar a Câmara Municipal de Pindamonhangaba-SP e seus vereadores. Substitui um Power BI de contagens manuais.

## Decisões do dono do projeto (24/10/2026)

- **Só Pindamonhangaba:** Observatório Social do Brasil – Pindamonhangaba e Câmara Municipal de Pindamonhangaba. Nada de outros observatórios ou municípios.
- **Só free tier:** nenhum serviço pago, nenhum cartão, nenhum domínio comprado (endereço `*.vercel.app`). Sem IA paga.
- **Atualização semanal** (quarta de manhã, depois da sessão de terça) + disparo manual.
- **Não é um clone do site da Câmara:** é um portal para acompanhar todos os vereadores. Mostra ementa, metadados e contexto, e linka para o documento oficial; não republica texto integral.
- **Sem votações e sem presença na v1.** Atualização **quinzenal feita pelo dono** (Redeploy na Vercel); o coletor roda no build.

## Princípios inegociáveis

1. **Proveniência:** todo dado exibido tem fonte, URL original, data de coleta e, se houver, transformação/correção. Nenhum "número mágico": toda contagem leva à lista dos registros que a compõem, e um teste garante que número = tamanho da lista.
2. **Neutralidade:** o OSB é apartidário. Nada de ranking, nota, selo, semáforo, "melhor/pior", "produtivo", "assíduo/faltoso", "campeão", "destaque". Ordem padrão de vereadores: alfabética pelo nome parlamentar. Sem cores de partido.
3. **Fato ≠ métrica ≠ classificação ≠ interpretação ≠ resumo.** Rotular cada um. Inferência nunca aparece como fato. Conteúdo gerado por IA é rotulado como derivado, persistido (nunca gerado por requisição do cidadão) e sempre ao lado do documento original.
4. **Contexto obrigatório:** denominador, período e papel institucional (ex.: presidente não vota em matéria comum; "não votou" ≠ "ausente"; votação simbólica não tem voto individual).
5. **LGPD:** coletar só o que tem função pública. Textos de honrarias trazem dados pessoais de cidadãos comuns — não republicar em massa; linkar o original. Nomes de servidores só quando necessários.
6. **Nunca inventar dado para preencher lacuna.** Lacuna aparece como lacuna.

## Regras das fontes (resumo de `docs/research/camara-site.md`)

- Ordem de preferência: API oficial (`/jsonweb/web-aplicativo.php`, exige token de cidadão) → fragmentos HTML públicos (`/ajax/tramitacao/...`) → páginas HTML → PDF.
- **Nunca contornar a proteção anti-robô** da Câmara (LiteSpeed reCAPTCHA): sem trocar User-Agent para fugir do desafio, sem resolver captcha, sem proxy de terceiros. Se aparecer "Bot Verification", o coletor para e alerta.
- User-Agent honesto identificando o projeto e contato; ≥ 1 s entre requisições; cache por hash de conteúdo.
- **HTTP 200 com corpo vazio é erro** (é assim que a API responde sem token). Validar plausibilidade de toda coleta (queda brusca de volume = coletor quebrado, não "nenhum resultado").
- O site recusa alguns datacenters; GitHub Actions recebe o desafio anti-robô no HTML, mas acessa a API `/jsonweb/`. Detalhes no relatório.

- **Sem assinatura de IA** em commits, PRs, código, comentários ou docs (nada de "Generated by", "Co-authored-by Claude", badges).
- **Identidade Git** (local ao repo): `José Victor Honorato <33707633+vhonorato02@users.noreply.github.com>`. Não alterar config global.
- **Idioma:** interface, documentação e textos para o cidadão em português do Brasil. Código e identificadores técnicos em inglês; termos de domínio sem tradução boa ficam em português (`vereador`, `proposicao`, `tramitacao`, `sessao`, `votacao`) — proposta a confirmar na Fase Foundation.
- TypeScript strict, sem `any`/`as any`, validação de fronteira com Zod, sem catch vazio, sem mock em produção, sem dado falso silencioso, sem lógica de negócio em componente visual.
- Comentário só para decisão, restrição ou comportamento não óbvio.
- Tokens de design semânticos (sem hex espalhado no código).
